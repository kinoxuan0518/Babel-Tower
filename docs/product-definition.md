# Babel Tower —— 产品重定义（v0.4 方向）

> 一句话：**选中外币价格，让大模型告诉你"这个价对你是什么档位、值不值"。**

本文档记录把 Babel Tower 从"认知翻译层（什么都做一点）"收敛为"**只做价格 → 价值定位描述**"这一件事的产品决策。核心信念：**做专 >> 做多**。

> ⚠️ 修订记录：早期草稿曾设想"删掉 LLM、纯本地查表锚点"。**已否决。** LLM 不是累赘，而是本产品的核心价值——它在这里发挥的就是**价值定位的描述性价值**：用语言判断一个价格意味着什么。"=3 杯奶茶"这种机械锚点不是目标。

---

## 1. LLM 在这里到底做什么（产品的轴心）

我们要的不是"换算"（那是工具），而是 LLM 给出的**描述性价值判断**：

> 选中 `$50` →
> *"对你（上海·开发者·月入 2.5w）来说，$50 ≈ ¥358，属于**中等偏轻**的区间，不用太纠结。这类一次性买断的工具比订阅划算；如果你会反复用，值。"*

它做的是**价值定位**：这个价格在它的品类里是便宜/中档/偏贵？放到**你的**收入和在意点上是什么感觉？值不值、有没有更优解？——这些是查表给不出、只有语言模型结合**页面上下文 + 世界知识 + 你的画像**才能讲出来的东西。**这就是用户来的理由。**

---

## 2. 为什么仍要"收敛"（收敛的不是 LLM，是范围）

旧版让 LLM 同时干：价格价值判断、尺码/合身、术语解释、整页翻译。问题不在"用了 LLM"，在于**它什么都做一点，于是哪件都不够锋利**。

做专的含义是：**LLM 只做一件事——选中价格的价值定位描述。** 砍掉 term / size / translation 这些旁支。好处：

- prompt、画像、上下文全部为"价值判断"这一个任务服务，能打磨到很好。
- 一句话讲得清产品是什么 → 利于传播。
- 砍掉尺码/合身这类**容错率极低、错了就退货**的高风险功能。

BYOK 的门槛**保留并接受**——它是这份描述性价值的代价，不绕。（缓解见 §8。）

---

## 3. 核心机制：确定性与描述性"分工"（关键架构）

这是解决"LLM 幻觉会害人"这个老问题的办法——**把硬数字和软判断分开**：

```
选中文本
  → 是价格吗？（本地 parser 闸门，不是价格就完全沉默）
      → ① 本地确定性层：识别金额+币种 → 用缓存汇率算出 ¥ 值     ← 不经过 LLM，不会幻觉
      → ② LLM 描述性层：把(¥值 + 页面上下文 + 用户画像)交给模型
                         → 产出价值定位描述（档位 / 对你的意味 / 值不值）
      → 卡片：硬数字（¥358）打底 + LLM 的价值判断为主体
```

**分工原则**：
- **会算错就会害人的东西（换算）→ 交给确定性本地数学**，绝不让 LLM 报数字。
- **主观、需要语境和判断的东西（值不值）→ 交给 LLM**，它本来就是软判断，容错空间大。

这样既拿到了 LLM 的描述性价值，又把它幻觉的风险关在"不碰硬数字"的笼子里。现有 v3 代码其实已是这个雏形（price heuristic 算换算 + LLM 出 insight），重定义只是**把 LLM 的职责收窄到"价值定位"这一个**。

## 4. 触发与场景边界

### 触发闸门（解决"太吵"）
旧版 auto 模式每次选中文本都弹卡片。新设计——**只在"选中内容被识别为价格"时才调用 LLM 弹卡片，非价格选中完全沉默。**

理由：人很少专门选中一串价格；一旦选了价格，大概率正在判断"值不值"。用"是不是价格"当闸门，既免去右键摩擦，又不会在阅读/复制时乱弹，**还顺带把 LLM 调用次数（= 成本）压到只在真有意图时发生。**

### 价值判断要随金额"换语气"
| 价格区间（CNY 等值） | 用户心理 | LLM 描述的重点 |
|---|---|---|
| 小额 < ~100 | 半冲动 | 轻快定调："随手买的价，值不值在于你用不用得上" |
| 中额 ~100–1000 | 半理性 | 给档位 + 对收入的分量 + 一句取舍建议 |
| 大额 > ~1000 | 理性决策 | 更克制：给品类档位/有无更优解，**不轻佻**，承认"这需要你认真比一比" |

**In scope**：你没有直觉的外币 + 中小额、半冲动购买（日亚、Etsy、海外订阅、独立站…）是甜区，但大额也给（只是换严肃语气）。
**Out of scope（明确砍掉）**：尺码/合身、术语解释、整页翻译、身体数据。

---

## 5. 用户画像：LLM 价值判断的"个性化"来源

价值定位若不结合"你是谁"就是废话（同样 $50，对学生和对总监意义完全不同）。喂给 LLM 的画像应**零配置先能用、想准再调**：

- **收入档位**（一个数/一个区间）—— 让"对你贵不贵"成立，最关键。不填则降级为"客观档位描述"。
- **地区 / 币种** —— 默认可从浏览器推断。
- **在意点 / 价格敏感度**（可选）—— "我对效率工具大方、对衣服抠"之类，让判断更贴。

原则：**绝不一上来甩一张表让用户填**；引导极简、跳过也能用。画像越全，描述越戳，但永远不卡流程。

---

## 6. 隐私：诚实的边界

这一版**确实会把"选中的价格 + 页面上下文"发给用户自配的 LLM**——这是描述性价值的必要代价，话术必须诚实，不能再喊"纯本地"：

- ✅ API key 存在浏览器本地，我们不碰、不中转到自有服务器。
- ✅ 汇率换算在本地完成。
- ⚠️ **价值判断需要把选中文本+页面上下文发给你选择的 LLM 提供商**（OpenAI/Gemini/…）。我们只发"做这次判断所必需的最少信息"，且**只在你主动选中价格时**发生（见 §4 闸门）。
- ⚠️ 显示的换算是**汇率中间价**，非到手价（刷卡有点差手续费），卡片措辞用"参考"。

诚实叙事 = "key 在你手里、只在你选价格时发、只发最少必要信息"，而不是假装不联网。

## 7. MVP 范围

**做**：
1. 价格/币种识别（打磨现有 parser，覆盖 `$1,299.00` / `1.299,00 €` / `¥` / `JPY 1,200` 等——**识别准确率是体验生死线**）。
2. 本地确定性换算（复用现有多源 FX，已移除失效的 exchangerate.host）。
3. **LLM 价值定位描述**（单一任务、专门打磨的 prompt；输入=¥值+页面上下文+用户画像；按金额换语气）。
4. 极简画像引导（收入档位为主，可跳过）。
5. 价格触发闸门 + 极简卡片（硬数字打底 + LLM 判断为主体）。

**不做**：尺码、合身、术语解释、整页翻译、页面意图分类做成独立功能（页面上下文仅作为价值判断的输入）。

**已完成的前置清理**：root 旧版 v1 单体文件（`content.js` 等 6 个 + root `icons/`）已删除，仓库现为 v3 单一基线。

## 8. 仍然存在、不替你藏起来的风险

| 风险 | 说明 | 应对方向 |
|---|---|---|
| **BYOK 门槛**（已知接受） | 目标用户里很多人不会配 key | 把"为什么值得配"在 onboarding 讲透；远期可选托管一个便宜小模型代理降门槛 |
| **LLM 调用成本/延迟** | 每次选价格 = 一次调用 | 闸门 + 缓存（同价同上下文命中缓存）；卡片先出硬数字再补判断，体感不卡 |
| **判断质量参差** | 不同模型/小模型判断可能平庸或翻车 | prompt 专门打磨；给"硬数字始终对"的兜底，判断只是增值层 |
| **低频** | 海淘非天天发生 | 接受它是"偶尔救命的好工具"，勿因此又"做多" |
| **易抄 / 难变现** | 单功能 | 壁垒在判断质量 + 画像个性化 + 体验；变现路径早想（Pro？托管代理订阅？） |

---

## 9. 一句话总结

把 Babel Tower 重定义成：**选中外币价格，LLM 结合你的画像与页面上下文，给出"这个价对你是什么档位、值不值"的价值定位描述；换算交给本地确定性数学，判断交给 LLM。** 产品功夫从"做四个功能"转移到"把这一个价值判断的 prompt、画像、体验打磨到极致"。
